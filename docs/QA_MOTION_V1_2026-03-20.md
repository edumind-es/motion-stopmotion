## Correccion aplicada durante la QA

Se detecto un mensaje de camara engañoso en entorno local cuando la app se servia desde `127.0.0.1`.

Antes:

- la UI sugeria usar HTTPS o localhost aunque el problema real era ausencia de dispositivo o permisos
- el fallback de camara registraba `console.error` aunque la aplicacion ya manejaba el fallo de forma controlada

Despues:

- `src/main.ts` reconoce `127.0.0.1`, `::1` y hosts `.localhost` como contexto local valido para el mensaje de ayuda
- `src/camera.ts` rebaja el fallo final de camara a `console.warn` para evitar falsos errores de runtime

## Hallazgos y riesgos residuales

### Sin bloqueo web inmediato

- la build web y la UI principal pasan la QA tecnica actual

### Pendiente de validacion fisica

- no se ha podido validar captura real de camara, permisos reales ni calidad de frame en este entorno
- no se ha podido ejecutar QA nativa Android porque el host no tiene Java
- no se ha podido ejecutar QA iOS porque este entorno no dispone de toolchain Apple

### Seguridad y dependencias

`npm audit --omit=dev --json` informa de 7 vulnerabilidades altas transitivas, principalmente en la cadena de `vite-plugin-pwa` / `workbox-build` / `rollup`.

Impacto practico actual:

- no bloquea la build ni el uso inmediato de la app
- si se va a desplegar en produccion, conviene abrir una iteracion especifica de actualizacion y hardening de dependencias

### Compatibilidad

- Vite avisa de que `baseline-browser-mapping` esta desactualizado
- conviene actualizarlo para mantener una matriz de compatibilidad mas reciente

## Conclusión

La QA completada valida que `motion_v1` esta estable a nivel web, responsive y de shell interactiva. La siguiente iteracion recomendada es una QA funcional con dispositivo real:

- permisos y seleccion de camara
- captura de varios frames
- reproduccion de timeline con playhead
- exportacion WebM, ZIP y PDF con material real
- comprobacion en tablet y movil fisico
